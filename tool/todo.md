# Deployment Configuration Tasks

## Use the Configurator

Open `g-configurator.html` in your browser, fill in your values, and download both files.
That handles everything below automatically.

---

## Frontend Configuration

- [ ] **Update `gnoke-config.js`** *(generated by configurator)*
    - Set `GNOKE_ENDPOINT` (API URL).
    - Set `GNOKE_REG_SECRET` (staff self-registration auth code).
    - Define collections in `GnokeStore.define()` (set scopes: user, workspace, or company).

## Backend Configuration

- [ ] **Update `api/gnoke-config.php`** *(generated by configurator)*
    - [ ] **DB_PATH**: Verify path or move `.db` outside web root for security.
    - [ ] **ADMIN_SECRET**: Change this to protect OTP generation and token revocation.
    - [ ] **MASTER_COLLECTIONS**: Define server-owned collections (e.g., price lists, products).
    - [ ] **ROLES**: Define RBAC roles or leave as `[]` for default access.
    - [ ] **OTP_TTL**: (Optional) Adjust from the 15-minute default if required.

---

### Deployment Notes ⚠️
- **Two files only**: `gnoke-config.js` and `api/gnoke-config.php`. Everything else is frozen — do not edit.
- **`index.html` is frozen**: `GNOKE_ENDPOINT` and `GNOKE_REG_SECRET` are read directly from `gnoke-config.js` — no duplicate values to keep in sync.
- **Static Files**: Do not modify `api/gnoke/*.php` or core engine files (`gnoke-store.js`, `gnoke-sync.js`, etc.).
